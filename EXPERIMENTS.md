# PIT Mutation-Operator Experiment

## Purpose

This pilot experiment examines how PIT mutation-operator selection changes the number of generated mutants, mutation score, runtime, and usefulness of the results for the same Java program and test suite.

The experiment asks:

> How does selecting a small, default, or comprehensive PIT mutator set affect mutation-testing results for the VendingMachine project?

## Environment

- Experiment date: August 21, 2026
- Project: `VendingMachine2`
- Local operating system: Windows 11
- Local Java runtime: Eclipse Temurin 21.0.12
- CI Java runtime: Eclipse Temurin 8
- Apache Maven: 3.9.16
- JUnit: 4.12
- JaCoCo Maven plugin: 0.8.13
- PIT Maven plugin: 1.6.8
- Test suite: 22 passing JUnit tests

The source and tests remained unchanged between runs. Only the selected PIT mutators changed.

## Reproduction

Run the following commands from the repository root.

### 1. Verify the normal test suite

```powershell
mvn clean test
```

Expected result: 22 tests run with no failures or errors.

### 2. Small conditional set

```powershell
mvn "-Dmutators=CONDITIONALS_BOUNDARY,NEGATE_CONDITIONALS" "-DreportsDirectory=target/pit-small" "-DtimestampedReports=false" test-compile org.pitest:pitest-maven:mutationCoverage
```

### 3. PIT default set

```powershell
mvn "-Dmutators=DEFAULTS" "-DreportsDirectory=target/pit-defaults" "-DtimestampedReports=false" test-compile org.pitest:pitest-maven:mutationCoverage
```

### 4. All available operators

```powershell
mvn "-Dmutators=ALL" "-DreportsDirectory=target/pit-all" "-DtimestampedReports=false" test-compile org.pitest:pitest-maven:mutationCoverage
```

## Results

| Configuration | Selected mutators | Generated | Killed | Survived | Timed out | Test strength | PIT analysis time |
|---|---|---:|---:|---:|---:|---:|---:|
| Small | `CONDITIONALS_BOUNDARY,NEGATE_CONDITIONALS` | 15 | 14 | 1 | 0 | 93% | 1 second |
| Default | `DEFAULTS` | 29 | 28 | 1 | 0 | 97% | 2 seconds |
| Broad | `ALL` | 326 | 260 | 65 | 1 | 80% | 9 seconds |

All three runs reported 53 of 55 lines covered (96%) and zero mutations without coverage.

The mutation score changed even though the tests did not. This demonstrates that a mutation score is meaningful only in the context of the mutator set used to calculate it.

## Default-Set Survivor

The sole survivor produced by the default mutator set was generated by `NegateConditionalsMutator` at the constructor loop condition:

```java
itemArray = new VendingMachineItem[NUM_SLOTS];
for (int i = 0; i < NUM_SLOTS; i++) {
    itemArray[i] = null;
}
```

Negating the loop condition prevents the explicit assignments of `null`. However, Java automatically initializes every element of a newly allocated object array to `null`. The original and mutated implementations therefore have the same externally observable behavior.

This survivor is a likely equivalent mutant rather than evidence of a missing test. A behavioral test cannot distinguish the two implementations because they produce the same state.

## Interpretation

The small conditional set reduced execution time and mutant count, but its one survivor represented a larger portion of the total and lowered the score to 93%.

The default set produced a compact and interpretable result. It retained the equivalent survivor while avoiding much of the noise introduced by broader and experimental operators.

The `ALL` set increased the mutant count from 29 to 326. It also produced 65 survivors and one timeout. Several enabled operators are aggressive, experimental, or overlapping, so the larger number of mutants does not automatically provide a better CI signal.

For this project, the default mutator set appears more practical for routine CI. The broader set is more appropriate for targeted investigation in which survivors and timeouts will be reviewed individually.

## Limitations

- This is a pilot study involving one small Java project.
- The likely equivalent mutant was classified through manual inspection, not an automated classifier.
- The 65 broad-set survivors have not been individually labeled.
- The experiment does not establish how these findings generalize to larger real-world projects.
- Local runs used Java 21 while the current GitHub Actions workflow uses Java 8.
- Mutation scores from different operator sets should not be compared as if they measured an identical population of faults.

## Next Research Step

The next step should be selected with the research mentor. Possible directions include manually labeling a sample of broad-set survivors, repeating the protocol across multiple Java projects, or evaluating a method that prioritizes likely equivalent mutants for human review.
